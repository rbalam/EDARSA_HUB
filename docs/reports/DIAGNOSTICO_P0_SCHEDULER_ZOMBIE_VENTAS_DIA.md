### 3.1 Problema Identificado: `--reload` en Ambiente Operativo

**CAUSA RAÍZ CONFIRMADA**: El flag `--reload` de uvicorn:

1. **Crea un proceso reloader padre** (PID 2745) que vigila cambios en archivos
2. **Spawns un worker hijo** (PID 2747) que ejecuta la aplicación
3. **Al detectar cambios**, mata el worker y crea uno nuevo
4. **PROBLEMA**: APScheduler se inicializa en el evento `@app.on_event("startup")` del worker
5. **DURANTE EL REINICIO**: El worker viejo puede seguir ejecutando jobs mientras el nuevo inicia
6. **RESULTADO**: Dos schedulers corriendo simultáneamente con diferentes estados

### 4.2 Análisis de `scheduler_manager.py`

El `SchedulerManager` implementa patrón Singleton:

```python
class SchedulerManager:
    _instance: Optional["SchedulerManager"] = None
    _initialized: bool = False
    
    def __new__(cls, *args, **kwargs):
        """Singleton pattern."""
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

**PROBLEMA**: El singleton es a nivel de proceso. Cuando uvicorn `--reload` crea un nuevo proceso:
- El nuevo proceso tiene su propio namespace
- La variable de clase `_instance = None` se reinicia
- Se crea una NUEVA instancia del scheduler

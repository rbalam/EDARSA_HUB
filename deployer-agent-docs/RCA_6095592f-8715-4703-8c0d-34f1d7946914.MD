## Root cause — path-fragile guardrail
`validate_enterprise_navigation.js` builds a signature per discovered tab and compares it against `src/config/enterpriseTabBaseline.json` (`signatures[]`, all prefixed `frontend/src/...`). The signature's file-path prefix is computed **relative to the frontend directory's PARENT**:

```js
const relative = path
  .relative(
    path.resolve(FRONTEND, ".."),   // parent of the frontend dir
    file
  )
  .split(path.sep)
  .join("/");
```
`FRONTEND = path.resolve(__dirname, "..")`, i.e. wherever the frontend is mounted.

The prefix therefore depends on WHERE the frontend is mounted:
- Repo / preview / eph sandbox / the R2 push step (`build-frontend-artifacts.sh` runs from `${SOURCE_DIR}/frontend`): frontend lives at `<root>/frontend` → prefix `frontend/` → **matches baseline → PASS**.
- Docker `frontend-build` stage in `Dockerfile.cloudbuild`: `COPY frontend/ /app/` with `WORKDIR /app`, so the frontend is at `/app` (NOT `/app/frontend`) → `path.resolve(FRONTEND,"..") = /` → prefix becomes `app/` → **NONE of the `app/src/...` signatures match the `frontend/src/...` baseline → every tab flagged `NEW_TAB_WITHOUT_ENTERPRISE_ID` → build fails.**

The `COPY frontend/ /app/` layout is standard, correct farm-template behaviour; the fragile assumption is in the app's guardrail. That is why it passes locally/in preview but fails only inside the Docker image build.

### Reproduced in the eph sandbox (run's own pulled source)
- From the repo layout (`/app/scratch/frontend`): `ENTERPRISE_NAVIGATION_GUARDIAN=PASS` (exit 0).
- From an `/app`-style layout (frontend contents copied to a dir named `app`): reproduced **byte-for-byte** — `ERROR=NEW_TAB_WITHOUT_ENTERPRISE_ID:app/src/pages/AuditoriasProgramadas.jsx|programadas|1 …` (exit 1), matching the Cloud Build log exactly.

## Fix (verified in eph pod) — app source, E1 to apply
File: `frontend/scripts/validate_enterprise_navigation.js`

Make the signature prefix independent of the mount location by anchoring it to the frontend root with a stable `frontend/` prefix. Replace:
```js
const relative = path
  .relative(
    path.resolve(FRONTEND, ".."),
    file
  )
  .split(path.sep)
  .join("/");
```
with:
```js
const relative = "frontend/" + path
  .relative(
    FRONTEND,
    file
  )
  .split(path.sep)
  .join("/");
```

Why this is correct: `path.relative(FRONTEND, file)` yields `src/pages/…` in **every** layout (repo, `/app`, `/app/frontend`, `/workspace/source/frontend`); prefixing a literal `frontend/` reproduces exactly the baseline's `frontend/src/…` signatures everywhere. No baseline regeneration needed.

Verification after patch (in the sandbox, `/app`-style layout that previously failed): `ENTERPRISE_NAVIGATION_GUARDIAN=PASS` (exit 0); still PASS from the repo layout.

`validate_executive_navigation.js` was checked from the same `/app`-style layout and passes unchanged (it keys off routes/components, not file-path signatures) — no change required there.
